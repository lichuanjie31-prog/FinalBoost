# FinalBoost 首版开发设计

日期：2026-09-15  
状态：供评审的设计草案，尚未开始代码实现。  
依据：[API 接口文档](./FinalBoost-API-v1.0.md)。

## 1. 本轮目标

在没有真实试卷和外部判卷凭据的情况下，先实现可运行的基础业务流程：

创建备考任务 → 上传任意测试图片 → 启动模拟判卷 → 查询状态 → 查看示例诊断。

测试图片可使用自行制作的简单样例。模拟服务不读取图片内容推断分数，只根据预设场景返回固定结果。页面始终展示“模拟数据，仅用于流程联调”。完成本轮仅代表业务流程可运行，真实识别和评分效果另行验收。

## 2. 三种推进方式

| 方案 | 产出 | 取舍 |
| --- | --- | --- |
| 前端静态原型 | 页面和演示交互 | 适合先讨论视觉，无法验证服务端任务及持久化 |
| 基础业务加模拟判卷，建议采用 | 前后端可联调的完整小流程 | 能提前验证任务状态、权限、失败恢复；需要后端基础建设 |
| 先完成全部数据库和接口 | 较完整的服务端框架 | 初始工作量较大，较晚获得可操作的流程 |

本设计采用第二种方案。后端使用用户确定的 Python / FastAPI，前端使用 React。本地联调暂按 SQLite 和本地文件目录设计，数据库选择属于待评审方案。首轮运行一个后端进程和一个后台任务执行器，降低本地运行复杂度；正式部署的数据库与任务执行方式在部署设计中确定。

## 3. 本轮范围

### 纳入

- 创建和查询备考任务。
- 图片上传、校验、保存及鉴权读取。
- 创建判卷任务、持久化状态、查询结果。
- 可切换的判卷服务接口，首轮提供模拟实现。
- 根据模拟判卷结果保存示例诊断。
- 最小操作页面：任务表单、上传、状态和诊断结果。
- 错误提示、幂等提交和资源归属检查。

### 后续阶段

- Agent 对话、工具自主选择和 SSE。
- 真题导入、向量检索和推荐算法。
- 专项训练、掌握度更新、最终模拟和 PDF。
- 真实判卷适配、评分效果实验和完整身份服务。

本轮通过判卷状态查询驱动页面。后续加入 SSE 时，查询接口仍用于刷新和断线恢复。

## 4. 组件与边界

| 组件 | 负责内容 | 对外输出 |
| --- | --- | --- |
| 考试模块 | 创建任务、校验目标分数、资源归属 | examId 与考试详情 |
| 文件模块 | 文件校验、存储、受保护下载 | fileId 与文件元信息 |
| 判卷模块 | 幂等受理、状态转换、结果落库 | gradingId、status、result、error |
| 判卷适配层 | 提交供应商任务、获取供应商状态 | 统一的供应商任务引用及标准化结果 |
| 后台执行器 | 领取任务、重试临时错误、处理超时 | 持久化任务状态 |
| 诊断模块 | 读取成功结果、按规则聚合示例知识点 | diagnosisId 与诊断内容 |
| 前端 | 请求、轮询、展示、重新加载后恢复 | 可操作的学习流程 |

模拟实现和未来真实实现使用相同的判卷适配层契约。供应商原始结果只在服务端保存，前端读取 FinalBoost 标准化字段。

## 5. 核心数据模型

所有主键使用不透明字符串。时间字段统一保存带时区时间；实体均包含 createdAt、updatedAt。

| 实体 | 关键字段 | 关系与约束 |
| --- | --- | --- |
| User | id、externalSubject | externalSubject 唯一；预留身份服务关联 |
| Exam | id、userId、course、examDate、targetScore、maxScore、stage | userId 关联 User；targetScore 不超过 maxScore |
| File | id、userId、storageKey、originalName、mimeType、size | storageKey 唯一，由服务端生成，禁止客户端指定磁盘路径 |
| GradingJob | id、userId、examId、status、provider、providerTaskId、nextPollAt、deadlineAt、leaseUntil、result、error | examId 必须属于 userId；result/error 按任务状态互斥 |
| GradingFile | gradingId、fileId、pageIndex | gradingId 加 pageIndex 唯一；文件属于任务用户 |
| Diagnosis | id、examId、gradingId、estimatedScore、outline、weakPoints、source | gradingId 唯一，确保重复生成读取同一诊断 |
| IdempotencyRecord | userId、method、path、key、requestHash、responseStatus、responseBody、expiresAt | userId、method、path、key 联合唯一 |

首版题目级批改结果保存为结构化 JSON，包含 questionId、score、maxScore、knowledgePointIds、errorType 和 errorReason。正式训练模块引入独立 Question、KnowledgePoint、Attempt、MasteryEvidence 表时，再建立题库外键。

诊断记录 source 为 mock 或 provider。模拟与真实数据不混合计算掌握度和历史成绩。

## 6. 模拟数据方案

样例考试满分 100，固定四道示例题，所有知识点和评分均为人工构造的联调数据。

| 题目 | 知识点 | 满分 | 样例得分 | 示例结果 |
| --- | --- | --- | --- | --- |
| demo_q1 | 链表 | 20 | 20 | 正确 |
| demo_q2 | 二叉树遍历 | 25 | 15 | 遍历顺序错误 |
| demo_q3 | Dijkstra | 30 | 10 | 松弛操作错误 |
| demo_q4 | 排序 | 25 | 18 | 中间步骤遗漏 |

总分为 63/100。诊断只聚合上述固定评分与知识点，展示“示例诊断”。知识点得分率分别为 100、60、33.3、72。mastery 保持 null，因为当前还没有实现画像算法。

四种模拟场景由服务端开发配置选择，公共请求体不增加测试开关：

| 场景 | 状态变化 | 预期表现 |
| --- | --- | --- |
| success | queued → running → succeeded | 返回四道题及完整诊断 |
| unreadable | queued → running → failed | error.code=42201，提示更换清晰图片 |
| provider_error | queued → running → failed | error.code=50201，提示稍后重试 |
| timeout | queued → running → failed | 超过任务时限后 error.code=50401 |

模拟运行约 3 秒完成，超时场景可在自动化测试中使用可控制时钟。生产启动配置不得默认启用模拟身份或模拟判卷。

## 7. 接口与状态约束

复用已编写文档中的以下接口：

- POST /exams。
- GET /exams、GET /exams/{examId}。
- POST /files/images、GET /files/{fileId}。
- POST /grading、GET /grading/{gradingId}。
- POST /exams/{examId}/diagnosis。

为让前端明确区分模拟数据，建议在判卷结果与诊断响应 data 增加 source 字段，值为 mock 或 provider。该项在编码前同步到 API 文档。

已完成任务不可回到 running。客户端重复同一幂等请求返回同一个 gradingId；用户主动重试失败任务使用新幂等键创建新任务，原失败记录保留。

异步任务创建与幂等记录在同一事务提交。后台执行器领取任务时写入租约，租约到期后允许重新领取；重启后扫描未终结任务继续执行。已取得 providerTaskId 的任务恢复时继续查询原任务。供应商提交结果不确定时保留提交标识并先查询，避免盲目重复提交造成重复收费。

任务默认时限建议为 120 秒，最多重试 2 次可恢复的上游网络错误，每次间隔 2 秒。不可识别图片直接失败。供应商正式接入时根据实测耗时调整配置。

## 8. 开发环境身份与文件

开发环境预置两名测试用户，由显式开发配置加载固定测试令牌。测试两名用户之间无法交叉读取资源。正常部署必须禁用此入口并接入身份服务。

本地文件保存在配置的上传目录，数据库保存 storageKey。下载按 fileId 查询归属后读取文件，上传文件名仅作显示用途。格式与大小限制沿用 API 文档。

服务重启后考试、文件引用和判卷任务仍能读取。文件目录必须持久化，不使用进程临时目录充当正式存储。

## 9. 开发与验收顺序

- [ ] 第一步：按 Python / FastAPI、React 和本地 SQLite 建立项目结构、配置与启动说明。
- [ ] 第二步：实现考试与文件接口，验证创建任务和图片读取。
- [ ] 第三步：实现模拟判卷、任务状态保存、幂等与重启恢复。
- [ ] 第四步：实现示例诊断，并在 API 文档补充 source 字段。
- [ ] 第五步：实现最小 React 操作页面，接入真实 HTTP 接口。
- [ ] 第六步：运行下列验收场景，记录实际结果后进入下一阶段。

| 场景 | 通过条件 |
| --- | --- |
| 完整成功流程 | 页面展示 63/100、四道题评分、示例薄弱点及模拟标记 |
| 同键重复提交 | gradingId 相同，后台只处理一次 |
| 同键不同参数 | 返回 HTTP 409 |
| 任务处理中刷新页面 | 能通过 gradingId 恢复查询，不创建新任务 |
| 两名用户交叉访问 | 无法读取对方考试、文件和判卷任务 |
| 不支持格式和超限文件 | 分别返回 415、413，界面显示原因 |
| 图片无法识别 | 显示明确失败原因，允许更换图片重新提交 |
| 上游失败与超时 | 进入 failed，客户端停止轮询 |
| 未完成时生成诊断 | 返回 HTTP 409 |
| 服务处理中重启 | 未终结任务恢复或在时限内明确失败，不永久卡住 |
| 分数一致性 | 四题得分和为 63，满分和为 100 |

验收记录包含测试场景、请求标识、实际结果和通过状态。模拟测试通过后，可继续训练与题库建设；真实判卷服务单独进行人工对照实验。
